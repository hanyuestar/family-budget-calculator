0. 一页纸摘要（给决策者）

它是什么

微信小程序，计算工具聚合器。首页卡片为统一入口，已上线 7 个计算工具（国潮塔罗、财富层级、存钱段位🔥、亲戚关系、家庭支出、BMI、时光进度条，塔罗为分包）+ 1 个历史记录中心，纯前端计算 + 本地存储 + 广告变现。

为什么做

填补"轻量、即时、不用下载 App"的家庭测算需求；以高频可分享工具换取广告曝光。

当前状态

10 个页面（首页 + 7 计算工具[含塔罗分包 2 页] + 历史记录中心）全部上线，172 项自动化测试通过（test_tarot 55 + test_all 117）；技术基建优秀（注册表驱动，加工具近乎零成本）；留存短板已部分缓解（本地历史中心已上线，仍属单机存储）。

北极星指标

周活跃工具使用次数（定义见 §6）。

下一步最高 ROI

① 加 1–2 个刚需工具（房贷 / 税后工资）；② 历史功能增强（去重 + 常驻入口 + 文案修正）。

最大风险

金融类工具审核措辞、本地存储敏感财务数据的隐私合规义务。

1. 问题陈述（Why）

1.1 背景

用户在日常生活中有大量"随手算一笔"的需求（支出汇总、BMI、存钱能力、亲戚称呼），但：① 打开 Excel / 记账 App 太重；② 零散的单一计算器小程序功能孤立、无法沉淀；③ 微信内缺少一个"轻、全、可分享"的聚合入口。

1.2 用户问题（痛点 → 假设标注）

痛点对应能力证据强度
家庭支出零散，算不清月度/年度总额家庭支出计算（15 项 + 饼图）内部逻辑合理；尚无用户调研数据支撑
不知道自己"算不算有钱"财富层级测试（7 级对标）同上
想存钱但没概念"能存多少"存钱段位 + 财富年龄同上
BMI 不知道胖瘦区间BMI 计算器（中国标准）同上
想直观感受"今年/人生过了多少"时光进度条同上（偏娱乐）
聚会时叫错亲戚称呼亲戚关系归约引擎同上
想娱乐化测试运势 / 心理投射（轻量、非算命）国潮塔罗（分包，22 张 + 3 牌阵）同上（偏娱乐，定位规避审核）
算完的结果没法留存，下次要重输历史记录中心（本地存储）内部逻辑合理；尚无留存率数据
⚠️ 数据诚实声明：以上痛点基于产品逻辑推导与常识，项目目前无任何用户调研 / 埋点数据。按产品规范，上线后应通过 §6 指标与用户访谈验证，避免"自嗨式需求"。

1.3 业务目标

  • G1（变现）：通过流量主广告实现稳定小额收入，单位经济模型依赖曝光量 × eCPM。
  • G2（留存）：以"本地历史 + 可分享的结果卡"提升复访与自发传播。
  • G3（扩展）：利用注册表基建持续低成本的加工具，扩大覆盖面与搜索命中。

1.4 非目标（Non-goals）★ 产品专家强制项

明确本产品不做什么，防止范围蔓延：

  • ❌ 不做完整记账 App（不与鲨鱼记账/随手记竞争，不建账本、不做分类统计报表）。
  • ❌ 不做社交 / 社区 / 排行榜（当前无账户体系，不引入社交关系）。
  • ❌ 不做专业财务顾问 / 投资建议（工具仅做"测算参考"，不构成任何建议）。
  • ❌ 不做跨端 Web App（当前以小程序为唯一载体）。
  • ❌ v1 不做账户体系 / 云端同步（本地历史中心已落地；跨设备永久留存列为后续演进，见 §9）。

1.5 成功指标预览

见 §6。上线后首季度以"建立埋点 + 拿到基线"为首要成功标准。

2. 目标用户与画像

  • 核心：关注家庭收支、想了解"钱花哪了"的普通家庭用户（25–45 岁，有育儿/房贷压力）。
  • 次级：对"财富段位 / 储蓄习惯 / 健康体重"有自我量化诉求的年轻用户。
  • 泛娱乐：节日/聚会需厘清亲戚称呼者；对"时间可视化"有兴趣者。
画像可信度：当前为假设画像，需在路线图一期安排 1 次用户访谈/问卷（见 §6、§12）校准。

3. 用户故事（User Stories）★ 新增

格式：作为 [角色]，我希望 [行为]，以便 [价值]

US-0（通用）：作为用户，我希望把计算结果保存为图片并分享给好友，以便把"我的数字"方便地传给他人。
US-1（家庭支出）：作为家庭财务负责人，我希望逐项填入支出后即时看到月度/年度总额与保险占比，以便判断开支结构是否健康。
US-2（财富层级）：作为资产配置者，我希望输入资产负债后知道自己的财富等级，以便对标"我在哪一层"。
US-3（存钱段位）：作为想存钱的年轻人，我希望算出储蓄率对应的"段位"和"财富年龄"，以便用趣味方式了解自己的储蓄习惯。
US-4（BMI）：作为关注健康的人，我希望输入身高体重得到 BMI 与中国标准分类，以便知道体重是否在健康区间。
US-5（时光进度条）：作为对时间敏感的用户，我希望自动看到今年/人生进度，以便直观感受时间流逝。
US-6（亲戚关系）：作为常参加家庭聚会的用户，我希望从"我"拼出关系链查到正确称呼，以便在亲戚面前不叫错人。
US-7（历史记录，已上线）：作为回头用户，我希望计算结果能自动留存在本机，以便下次打开无需重新输入、还能一键恢复重算。
US-8（暗色主题，已上线）：作为夜间或弱光下使用的用户，我希望能切换到暗色主题，以便不刺眼、更省电。
US-9（国潮塔罗，已上线）：作为想轻量娱乐测试运势的用户，我希望选牌阵抽牌后看到正/逆位解读并能保存分享长图，以便趣味自测与社交传播（定位"娱乐测试"，规避算命类目审核）。

  • 微信小程序原生（WXML / WXSS / JS），无跨端框架；

  • 开发者工具导入 miniprogram/，appid wx7fa128d056963af6。

4.3 模块 / 目录架构

├── behaviors/calc-page.js           通用页面行为：返回首页(带插屏)+分享骨架
├── components/calc-input/           通用输入行（¥ / 万元 / field 透传）
├── config/tools.js                   中央工具注册表（首页唯一数据源）
├── pages/  home · index(支出) · wealth · saving · bmi · progress · relation · history
├── subpackages/tarot/  pages(index/draw) · data/cards.js(22牌+3阵) · assets/jpg(22卡面)
└── utils/  format.js(金额) · report.js(canvas出图+存相册) · history.js(本地存储层)

4.4 核心设计模式：单一数据源 + 通用基建

  1. 中央工具注册表 config/tools.js：首页卡片唯一数据源；加工具 = 注册路径 + 加一条 {id, icon, name, desc, path, hot?}。
  2. 通用输入组件 calc-input：所有数字输入复用。
  3. 通用页面行为 calc-page：自动获得返回首页（带插屏）+ 分享骨架。
  4. 通用报告 report.js：7 工具共享 canvas 出图 + 存相册（塔罗额外用 canvas.createImage 异步加载卡面）。
  5. 通用历史存储 history.js：计算页 saveResult 自动 history.add；历史页读取/收藏/删除，restoreHistory 回填重算。
  6. 全局样式 app.wxss：.card / .btn* / .input-row / .ad-banner-wrap + 暗色主题 CSS 变量。
加新工具标准步骤（4 步）：① app.json 注册页面路径；② config/tools.js 加一项；③ 建页面四件套（.js 混入 calc-page、.json 注册 calc-input、输入用 calc-input、结果用 report.*）；④ 可选复用全局样式与 history.add 持久化。

9. 数据需求与规划（DATA-1）

9.1 当前状态

方案 A（本地存储）已落地：utils/history.js 提供 add / getAll / getByTool / star / remove / clear，各计算页 saveResult 自动写入本机，历史页可读取/收藏/删除/恢复重算。

  • 剩余短板：仍是单机存储——换手机、重装微信或清缓存即丢失；受 wx.setStorageSync 10MB 上限约束；不支持跨设备同步。
  • 跨设备永久留存仍待方案 B/C。

9.2 可选方案

方案持久化登录服务器成本适用状态
A. 本地存储单机（换机/清数据丢，10MB 上限）否否免费一期顶留存✅ 已落地
B. 微信云开发跨设备永久（openid 无感）否否~19.9 元/月要"永久留存"时待定
C. 自建 Docker 后端完全自控、可关系库否（wx.login）是（备案域名+HTTPS）~40–60 元/月+域名需完全掌控时待定

9.3 隐私合规（独立强调）

工资/家庭支出属个人信息，且现已落地本地存储（敏感财务数据留存本机），无论哪方案都须：

  1. 小程序后台填《个人信息保护指引》；
  2. 收集前弹 wx.requirePrivacyAuthorize 授权；
